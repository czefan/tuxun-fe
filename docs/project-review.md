# 项目检查记录（2026-09-28）

## 首页恢复问题

代码与回归测试确认了以下故障路径：

1. `onLaunch` 与 `onShow` 同时校验会话，迟到的响应可能覆盖登出或新的登录状态。
2. 会话失效时调用 `removeQueries()`，销毁页面仍在使用的查询；首屏请求尚未完成时，观察者可能一直停在 pending，手动刷新才恢复。
3. 全局关闭了前台恢复和联网恢复重拉，小程序也没有同步后台焦点；后台错过网络事件后还可能持续认为离线。
4. 会话校验没有识别 HTTP 200 携带业务 `code: 6` 的未登录响应。

现改为：每个会话只保留一个正在进行的校验、用运行期会话版本隔离旧响应、取消旧查询后等待登录状态更新再重置查询，以及同步前后台焦点和重新探测网络。普通请求默认超时从 60 秒调整到 15 秒；图片上传仍为 60 秒。权限或业务限制不再自动重试，临时故障最多重试一次。

## 结构和体验调整

- 保留现有分层与主包 / 分包结构，合并首页、活动题目页的重复列表实现。
- 登录判断共用基础 composable，清理仅做转发的用户域入口和未使用的点赞 store。
- 网络恢复由查询层统一处理，避免每个页面重复监听、重复使全站缓存失效。
- 修正带筛选条件的缓存失效范围；更新已读状态、投稿等操作能刷新对应筛选列表。
- 限定评论删除、公开答案点赞和提交作答的缓存更新范围，避免其他题目或 ID 恰好相同的不同记录被误改；切换账号时同步清理页面内的通知已读记录。
- 列表恢复显示时重拉过期数据；分页防重复、防止中断刷新，空页停止翻页，非活跃 Tab 不提前结束下拉动画。
- 搜索 300ms 防抖，清空时取消等待中的搜索；活动参数缺失时显示明确提示。
- 刷新 / 翻页失败时保留已有列表，题目列表底部提供重试入口。
- 渐进图片在缺少原图地址时使用可用图片；限制加载后的异常长图高度。
- 私有通知、个人信息与作答查询增加登录前置条件；通知详情失败时提供重试。
- 修正构建分析插件判断了错误的模式名，启用分析时可以实际生成报告。

## 技术栈与依赖

无需更换框架或增加状态管理、请求库。UniApp 仍负责 H5 / 微信小程序，Pinia 负责会话，TanStack Query 负责远端数据；这些职责没有重复。移除未使用的 `@dcloudio/uni-automator` 及其 Jest 依赖链，保留当前 Vitest 测试体系。

兼容修补通过 `pnpm-workspace.yaml` 的限定版本 overrides 固定，涉及 ws、Babel、PostCSS、选择器解析、js-yaml 和 fast-uri。锁文件随之更新，可通过 `pnpm install --frozen-lockfile` 安装。

截至本次检查，`pnpm audit --prod` 的告警由 21 项（9 高、10 中、2 低）降为 13 项（6 高、7 中）。该统计包含 UniApp 放在 dependencies 下的编译工具，并不等于这些模块都被打进客户端。剩余依赖主要来自：

- UniApp 编译链的 Vite 5 / esbuild，修复版本涉及框架绑定范围之外的升级。
- UniApp 的旧 Intlify、adm-zip，以及微信构建工具中 Jimp 使用的 jpeg-js / phin。

全量 `pnpm audit` 还包含小程序上传工具等开发依赖的历史告警。此次没有使用强制跨大版本覆盖把告警隐藏；后续应随 UniApp / 微信官方工具升级，重新验证开发服务、构建、登录和小程序真机流程。现有 peer 告警也涉及 UniApp 精确绑定的 Vue / Vite 与部分工具的旧声明，不能仅凭消除告警降级当前依赖。
