# 项目检查与优化（2026-09-29）

## 结论与范围

现有 Uni-app / Vue 3 / TypeScript 适合 H5 与微信小程序双端。Pinia 管理会话、TanStack Query 管理服务端缓存，职责合理；继续保留 pages / subPages → features → service 的分层，不建议为减少目录或追逐版本而迁移框架。

本轮检查覆盖依赖配置、架构约束、请求与上传、会话清理、查询缓存、投稿 / 作答 / 反馈 / 商城流程、公共加载状态、测试和构建。体验结论来自组件代码和自动化测试，没有进行浏览器视觉验收或微信真机操作；不能据此保证项目不存在其他问题。

## 已修改

| 问题                                                                                | 修复                                                                        |
| ----------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| 上传收到 HTTP 200 的 HTML、空内容、null、数组或空对象也返回成功，可能让页面清空表单 | 拒绝这些无效响应；保留现有业务 envelope 和旧对象格式兼容                    |
| 上传未等待 Mock worker 就绪                                                         | 与普通请求使用同一个 ensureMockReady，避免初始化期间透传                    |
| 作答完成时从响应式页面参数确定缓存更新对象                                          | 以实际提交 payload.photoId 为准，移除 mutation hook 对页面 ID getter 的依赖 |
| 作答路由 ID 为 0、负数、NaN 或非整数也能提交                                        | 提交前校验正安全整数并提示返回重新进入                                      |
| 表单只依赖按钮的 disabled，事件入口缺少重入保护                                     | 投稿、作答、反馈、兑换入口检查请求中状态                                    |
| 兑换可以重复打开确认框，确认期间商品信息可能变化                                    | 确认框锁；确认时重新检查登录、库存、价格、积分、弹窗可见性与请求状态        |
| 商城已有数据时翻页 / 刷新失败缺少恢复入口                                           | 保留商品，展示失败提示和重试按钮；区分重新翻页和全量刷新                    |
| 商城清空搜索仍等待防抖                                                              | 清空时取消待执行搜索并立即恢复列表                                          |
| 页面恢复时 refetch rejection 未捕获                                                 | 在公共列表生命周期中捕获，交由页面错误态反馈                                |
| 配置 skeleton 却没有传 loading 插槽会出现空白                                       | 提供默认加载指示器                                                          |
| H5 键盘焦点与减少动画支持不足                                                       | 增加 focus-visible 和 prefers-reduced-motion 样式                           |
| 检查脚本使用 process.exit，管道输出有被截断风险                                     | 正常检查收尾改用 process.exitCode，保留中断处理                             |

2. **异步状态隔离。** 后续优化已加入缓存版本与会话保护，并补充回归测试，详见下节。并发冲突通过重新查询校准。
3. **草稿与媒体生命周期。** 后续优化已完成字段校验、过期图片提示和 blob URL 释放；跨重启图片持久化仍未实现。
4. **类型与国际化。** 多个缓存更新仍用 any；页面正文存在硬编码中文，当前英文资源并不表示全站完整支持英文。应按业务域逐步补齐，不把类型断言当成运行时验证。
5. **上线前真机验收。** 校验 OAuth 登录 / 退出、后台会话过期恢复、断网重连、地图定位权限、图片 / 视频上传、兑换超时后的订单核对。兑换客户端重入保护不能替代服务端库存校验和幂等保障。

## 后续优化：草稿、媒体与并发状态

已继续落实前述第 2、3 项中的可直接修复问题：

- 将题目 / 评论 / 答案点赞、评论增删、商品兑换、头像 / 昵称的缓存快照保护统一到 `service/query/optimistic.ts`。失败时只回滚仍等于本次写入的数据；检测到后续修改时保留新值并重新查询。会话变化后的旧回滚不再恢复前一用户的数据，取消查询期间换会话会中止操作。
- 点赞结束后校准服务端数据；作答和个人资料的延迟成功响应增加会话保护。头像压缩期间也禁止重复确认。
- 评论发送使用显式的 `{ photoId, content }` 请求变量；删除评论使用操作开始时的题目 ID 刷新缓存，避免切题后更新错误对象。
- 投稿路由回填和投稿 / 作答草稿按字段白名单解析，拒绝错误类型、非法坐标、无效活动 ID，避免直接合并不可信对象。草稿读取 / 写入失败不阻断正常编辑。
- 恢复草稿前验证图片能否读取；图片失效时保留文字与坐标，并提示重新选图。延迟恢复时检查会话和页面是否已卸载。
- 投稿、作答、反馈共用媒体资源生命周期处理，替换、删除、卸载和延迟到达的旧选择释放 blob URL。连续选择时使用序号，防止较早的压缩结果覆盖新选择。
- 图片压缩释放未被选中的中间 blob；canvas 超时后到达的回调不再创建无主 URL。

这些改动没有引入新的依赖。图片仍采用临时路径，本轮修复了过期恢复与资源管理，未实现跨浏览器重启的持久图片草稿。发生并发冲突时以重新查询收敛；断网时需等待网络恢复才能得到服务器最终状态。

新增测试覆盖损坏草稿、字段白名单、过期图片、媒体替换 / 卸载 / 选择顺序、独立与并发回滚、切换账号、延迟作答响应及评论目标隔离。延续本报告的验证边界：不替代 OAuth、定位和上传的真机联调。

## 后续优化：登录竞争与页面退出

- 登录流程增加同会话共享的操作序号和会话版本校验，覆盖换取凭据、加载个人资料两个等待阶段；旧登录结果不覆盖新登录，当前登录失败统一清理本地状态。
- 登录回调页不再在任意失败时直接登出，避免旧回调失败清除新用户会话。认证服务返回的错误文本直接显示，避免重复 URI 解码遇到非法百分号时报错。
- 登出返回操作是否已被新会话取代，页面据此停止清理回跳路径和认证中心跳转。此保护针对前端状态；服务器对并发 cookie 请求的处理仍需联调确认。
- 登录回跳、题目切换的延迟导航在页面销毁时取消；切题同时兼容 Uni-app onUnload 和 Vue scope dispose。
- 评论弹窗关闭 / 卸载时取消聚焦、失焦定时器，延迟 nextTick 聚焦再次检查可见性；本地表情记录只接受支持的字符串。
- 来源筛选列表到达边界时直接返回无相邻题，不再从其他缓存列表继续跳转；找不到来源缓存时仍保留原有回退逻辑。
