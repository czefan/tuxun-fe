# 项目检查与优化（2026-09-29）

## 结论与范围

现有 Uni-app / Vue 3 / TypeScript 适合 H5 与微信小程序双端。Pinia 管理会话、TanStack Query 管理服务端缓存，职责合理；继续保留 pages / subPages → features → service 的分层，不建议为减少目录或追逐版本而迁移框架。

本轮检查覆盖依赖配置、架构约束、请求与上传、会话清理、查询缓存、投稿 / 作答 / 反馈 / 商城流程、公共加载状态、测试和构建。体验结论来自组件代码和自动化测试，没有进行浏览器视觉验收或微信真机操作；不能据此保证项目不存在其他问题。

## 已修改

| 问题                                                                                | 修复                                                                        |
| ----------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| 上传收到 HTTP 200 的 HTML、空内容、null、数组或空对象也返回成功，可能让页面清空表单 | 拒绝这些无效响应；保留现有业务 envelope 和旧对象格式兼容                    |
| 上传未等待 Mock worker 就绪                                                         | 与普通请求使用同一个 ensureMockReady，避免初始化期间透传                    |
| 作答完成时从响应式页面参数确定缓存更新对象                                          | 以实际提交 payload.photoId 为准，移除 mutation hook 对页面 ID getter 的依赖 |
| 作答路由 ID 为 0、负数、NaN 或非整数也能提交                                        | 提交前校验正安全整数并提示返回重新进入                                      |
| 表单只依赖按钮的 disabled，事件入口缺少重入保护                                     | 投稿、作答、反馈、兑换入口检查请求中状态                                    |
| 兑换可以重复打开确认框，确认期间商品信息可能变化                                    | 确认框锁；确认时重新检查登录、库存、价格、积分、弹窗可见性与请求状态        |
| 商城已有数据时翻页 / 刷新失败缺少恢复入口                                           | 保留商品，展示失败提示和重试按钮；区分重新翻页和全量刷新                    |
| 商城清空搜索仍等待防抖                                                              | 清空时取消待执行搜索并立即恢复列表                                          |
| 页面恢复时 refetch rejection 未捕获                                                 | 在公共列表生命周期中捕获，交由页面错误态反馈                                |
| 配置 skeleton 却没有传 loading 插槽会出现空白                                       | 提供默认加载指示器                                                          |
| H5 键盘焦点与减少动画支持不足                                                       | 增加 focus-visible 和 prefers-reduced-motion 样式                           |
| 检查脚本使用 process.exit，管道输出有被截断风险                                     | 正常检查收尾改用 process.exitCode，保留中断处理                             |

新增回归用例覆盖无效上传响应、作答缓存目标、恢复页面异常、兑换重复确认及确认期间的状态变化。

## 后续优先事项

1. **依赖升级单独验证。** 上轮记录中的 Uni-app / Vite / 微信工具链安全告警需要跟随官方兼容版本处理。本轮没有联网重新审计，因此不提供新的漏洞数量，也不强制跨大版本覆盖依赖。
2. **异步状态隔离继续加固。** 部分乐观更新采用整份缓存快照回滚；多个操作并发失败、操作期间切换账号需要更系统的测试，再考虑逐记录回滚和会话版本隔离。
3. **草稿与媒体生命周期。** 投稿与作答仍使用临时图片路径，浏览器刷新或小程序临时文件过期后不能保证恢复图片；恢复对象应逐字段校验，H5 自建 blob URL 应在替换和卸载时释放。后续适合统一草稿与媒体选择逻辑，避免各页面重复维护。
4. **类型与国际化。** 多个缓存更新仍用 any；页面正文存在硬编码中文，当前英文资源并不表示全站完整支持英文。应按业务域逐步补齐，不把类型断言当成运行时验证。
5. **上线前真机验收。** 校验 OAuth 登录 / 退出、后台会话过期恢复、断网重连、地图定位权限、图片 / 视频上传、兑换超时后的订单核对。兑换客户端重入保护不能替代服务端库存校验和幂等保障。

本轮未部署、未调用生产写入接口。
